# 反馈追踪与内部迭代

用户的意见往往指出一个可观察的问题。把它变成能实际验证的修改目标，并检查同一原因是否影响相邻内容或另一种成品。

## 成稿前内部试用

- 用读者会采取的顺序试用成稿。先顺读一处术语密集或步骤复杂的内容，再尝试根据背诵要点回答一题，最后从答案或考点回查原证据。纸面成品按最终页行定位，电子成品实际走一次作答与查答案流程。
- 记录试用时卡住的地方及其后果，例如公式缺单位会使答案不唯一，词义解释过晚会使下一段无法理解，页行引用漂移会使纸面无法定位。逐项回到证据、结构或版面修复，再从原卡点试一次。
- 将复核扩大到问题可能重复出现的范围，例如检查全文第一次出现的简称，或检查所有重排后受影响的跳转。当前目标已通过回读或实测时收尾，无法消除的证据缺口保留可定位的说明。

## 从反馈到交付

1. **定位当前版和修改范围。** 拿到被指的原文、题号、章节、表列或链接目的地。核对用户说的是印刷版、网页、背诵稿、全量稿还是源表。若问题同时出现在两份材料中，一起查共同底稿。只要求解释或暂停时按该范围处理。
2. **按问题回到证据或结构。** 重现错误并判断属于来源、转写、归纳、写作、判分还是排版。可先修一个有代表性的样段并通读，再据结果推广。关键来源缺失时继续处理可证实的部分，将会改变结论的疑点编号并集中反馈。
3. **先改产生错误的位置。** 修改源表或内容底稿，并查哪些章节、题解、图注、网页数据和目录引用依赖它。用户新增的事实与本轮交付偏好按实际效力记入项目。保留已有的题号与旧版以便比较。
4. **回读对照。** 对每条意见检查修改前后是否确实解决了指出的问题。重跑受影响的题目与链接校验，并抽查同类型位置。必要时重新导出、回读索引和经授权的备份。只汇报已经落地的改动和仍待解决的疑点。

## 常见反馈与复查动作

| 反馈 | 复查及写回动作 |
| --- | --- |
| “转写错别字多，可能漏了考点” | 找到读者看到的是原文栏还是校订摘要。重查录音短窗和对应课件页，尤其关注否定、比较关系、数值和题型词。按课件反查未命中的知识点。修正证据等级与实际漏题，将新增条目接回题号 |
| “从某一章开始读不懂” | 从读者卡住的位置回看前置概念、操作目的和条件。先理顺这一章，再查相邻章节有没有缺过渡。在该处解释必要简称、比较对象和步骤，搭配有用图表或按原题条件重算的例题 |
| “背诵稿和全套稿逻辑不统一，说明打断阅读” | 核对两稿的主线和术语，调整相同主题的先后。把重复的出处或版本提示收拢，正文保留定义、比较条件和关系。验收时分别模拟阅读理解与直接复述 |
| “保留现在内容，补齐简答” | 沿用既有题号与提纲，补完整提问及分点标准答法。在同题型中抽查答案是否真正回应问法，各点能否在出处或课件找到依据 |
| “老师说题型变了，重新审查重点” | 记录用户确认的事实和范围，重新对照录音、重点材料及原卷。调整覆盖和题型配比，标注新增同构题与旧题。口述大方向无法推出精确题量时保留未知 |
| “链接跨文件或打印定位失效” | 核对用户要的链接范围，从最终版面的正确目标重建书签、链接和页行引用，再实际打开 PDF 或解析跳转目标。相同修订覆盖涉及的 Word、PDF 和网页 |

需要追踪多处修改时，可在任务底稿里记 `问题编号 | 用户原意 | 改前位置 | 复核证据 | 修改及受影响成品 | 验证结果 | 待核项`。有歧义的确认项先编号再请用户集中核对。确认后按编号写回与回读，对仍不清楚的内容保留原图或原音定位。
